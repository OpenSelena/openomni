## Executive Summary

This research report investigates candidate features and architectural deepening opportunities for Open Omni v1.5.0, grounded strictly in the repository's primary sources (`src/`, `CONTEXT.md`, `docs/adr/`, and test suites). 

Open Omni's core strength is its frictionless terminal experience ("grab any video. paste. download. done.") combining `yt-dlp`, `gallery-dl`, and native Node HTTP stream resolvers under an Ink React TUI. However, several architectural bottlenecks and feature gaps currently constrain scaling, performance, and developer velocity:
1. **Batch Queue Concurrency**: Playlists and photo posts are downloaded strictly serially ([ADR 0001](file:///x:/Open%20Omni/docs/adr/0001-batch-download-architecture.md#L18-L19), [src/cli.tsx#L300](file:///x:/Open%20Omni/src/cli.tsx#L300), [src/app.tsx#L480](file:///x:/Open%20Omni/src/app.tsx#L480)). While serial downloading protects against rate-limits on YouTube, it severely degrades throughput on photo carousels (20–50 photos take 30–60s instead of 2–3s).
2. **Output Filename Templating**: `-o` and `--output` only accept directory paths ([src/lib/args.ts#L153-L160](file:///x:/Open%20Omni/src/lib/args.ts#L153-L160)), while `opts.outputTemplate` is supported by `ytdlp.download` ([src/lib/ytdlp.ts#L542](file:///x:/Open%20Omni/src/lib/ytdlp.ts#L542), [#L590](file:///x:/Open%20Omni/src/lib/ytdlp.ts#L590)) but entirely unexposed to CLI flags or configuration.
3. **Persistent User Configuration**: While `src/lib/config.ts` reads preferences on startup, it has **zero write capability**; users cannot persist format/theme/proxy choices made during interactive TUI sessions or via CLI commands.
4. **Live Clipboard Daemon (`--watch`)**: Clipboard reading is currently a one-shot synchronous probe during interactive launch ([src/cli.tsx#L428-L432](file:///x:/Open%20Omni/src/cli.tsx#L428-L432), [src/lib/clipboard.ts#L14-L23](file:///x:/Open%20Omni/src/lib/clipboard.ts#L14-L23)); adding a persistent `--watch` daemon enables seamless "copy link and it downloads in background" workflows.
5. **Platform Routing & Embed Resolvers**: `bsky.app` is omitted from `PLATFORMS` ([src/lib/platforms.ts#L10-L20](file:///x:/Open%20Omni/src/lib/platforms.ts#L10-L20)), and `tiktok.com` is omitted from `MIXED_OR_PHOTO_DOMAINS` ([src/lib/dispatcher.ts#L33-L52](file:///x:/Open%20Omni/src/lib/dispatcher.ts#L33-L52)), breaking TikTok slideshow downloads. Adding a native Bluesky resolver (`public.api.bsky.app`) mirrors the high-speed unauthenticated Instagram embed resolver ([ADR 0014](file:///x:/Open%20Omni/docs/adr/0014-native-instagram-embed-resolution.md)).
6. **Codebase Hygiene**: `src/app.tsx` has grown to **1,194 lines**, housing state machines, download loops, keyboard handling, and 12 distinct phase views. Decomposing it into custom hooks and views reduces cognitive load and enables isolated testing. Furthermore, `maskProxyCredentials` ([src/lib/ytdlp.ts#L474-L480](file:///x:/Open%20Omni/src/lib/ytdlp.ts#L474-L480)) only strips basic URLs, leaving API tokens, auth headers, and session cookies vulnerable to leaking in error logs.

## 1. Candidate Features for v1.5.0

### 1.1 Concurrent / Parallel Downloads in Batch Queue

#### Current State in Codebase
* **ADR 0001**: Explicitly selected serial processing: *"Concurrent downloads risk platform IP throttling/CAPTCHA rate-limits on YouTube and Instagram and degrade terminal UI readability. We process the batch queue serially (one item at a time) with dual progress indicators"* ([docs/adr/0001-batch-download-architecture.md#L18-L19](file:///x:/Open%20Omni/docs/adr/0001-batch-download-architecture.md#L18-L19)).
* **Headless CLI**: In `src/cli.tsx` ([#L300-L347](file:///x:/Open%20Omni/src/cli.tsx#L300-L347)), playlist downloads execute in a sequential `for (const entry of playlist.validEntries)` loop with single-item `downloadUnifiedItem` calls.
* **Interactive TUI**: In `src/app.tsx` ([#L480-L548](file:///x:/Open%20Omni/src/app.tsx#L480-L548)), `executeBatchDownload` runs a sequential `for (let i = 0; i < queue.length; i++)` loop, updating the phase state with a single active item's progress (`progress?: DownloadProgress`) and a single `currentIndex` ([#L101-L110](file:///x:/Open%20Omni/src/app.tsx#L101-L110)).
* **TUI Component**: `PlaylistProgress` ([src/components/playlist-progress.tsx#L10-L115](file:///x:/Open%20Omni/src/components/playlist-progress.tsx#L10-L115)) strictly renders two bars: `Overall Batch` and a single active `currentTitle` stream progress bar.

#### Limitations & Bottlenecks
* While serial downloading makes sense for long YouTube video batches to prevent HTTP 429/CAPTCHA bans, it introduces massive, unnecessary latency for **photo carousels and mixed-media posts** (e.g. 30 photos from Reddit or Instagram). Downloading 30 photos serially spawns 30 distinct `gallery-dl` processes or serial CDN requests taking ~45 seconds, whereas a concurrency of 4–6 finishes in ~3–5 seconds.
* The Download Ledger (`ledger.json`) uses synchronous un-locked file operations ([src/lib/ledger.ts#L55-L63](file:///x:/Open%20Omni/src/lib/ledger.ts#L55-L63)). If multiple parallel downloads complete concurrently, uncoordinated writes will produce race conditions and overwrite records.

#### Proposed Architecture & Implementation Plan
1. **Adaptive Concurrency by Media Type**:
   * `--concurrency <N>` / `-c <N>` CLI flag (default: `auto`).
   * In `auto` mode:
     * Video playlists (YouTube, Vimeo, etc.): Concurrency = `1` (preserves rate-limit safety per ADR 0001).
     * Photo / Multi-Asset Carousels (Reddit, Instagram, Bluesky, Twitter/X): Concurrency = `4`.
     * User can override `--concurrency 4` for high-throughput video servers if desired.
2. **Worker Pool / Semaphore Execution**:
   * Implement a lightweight async worker pool in `src/lib/pool.ts` or leverage a promise semaphore (`p-limit` pattern without native C-deps).
   * Support graceful `AbortSignal` propagation: cancelling aborts all active worker items simultaneously.
3. **Dual Progress Display Adaptations**:
   * For the TUI in `src/components/playlist-progress.tsx`:
     * Top bar: Overall batch completion percentage (`batchPct = completedCount / totalCount`).
     * Bottom section: Aggregated concurrent transfer metrics (sum of active stream speeds, total bytes transferred) with a scrolling or multi-slot list of currently active items (`[1/20] Active`, `[2/20] Active`).
4. **Ledger Concurrency Serialization**:
   * Wrap `recordDownloadWithStat` ([src/lib/ledger.ts#L123-L136](file:///x:/Open%20Omni/src/lib/ledger.ts#L123-L136)) with an in-memory Promise chain / FIFO write queue so concurrent task completions append safely to `ledger.json`.

### 1.2 Output Filename Templating (`--output` / `-o`)

#### Current State in Codebase
* **CLI Arguments**: In `src/lib/args.ts` ([#L153-L160](file:///x:/Open%20Omni/src/lib/args.ts#L153-L160)):
  ```ts
  } else if (arg === '-o' || arg === '--output') {
    const value = args[++index]
    if (!value) return {...result, error: `${arg} needs a directory path`}
    result.outputDir = value
  ```
  `-o` and `--output` are strictly resolved as directories via `resolveOutputDir` ([#L285-L295](file:///x:/Open%20Omni/src/lib/args.ts#L285-L295)).
* **Hardcoded Templates**:
  * Single videos in `ytdlp.download`: Lines [589-590 of src/lib/ytdlp.ts](file:///x:/Open%20Omni/src/lib/ytdlp.ts#L589-L590) hardcode:
    `-o`, `opts.outputTemplate ?? path.join(opts.outDir, '%(title).60s.%(ext)s')`
  * Playlist items in `formatTrackFilename`: Lines [49-60 of src/lib/playlist.ts](file:///x:/Open%20Omni/src/lib/playlist.ts#L49-L60) hardcode:
    `${paddedIndex} - ${cleanTitle}.${cleanExt}`
  * Unified dispatcher items in `downloadUnifiedItem`: Lines [588, 614, 640 of src/lib/dispatcher.ts](file:///x:/Open%20Omni/src/lib/dispatcher.ts#L588) invoke `formatTrackFilename`.

#### Proposed Architecture & Implementation Plan
1. **CLI & Config Syntax**:
   * Add dedicated flag `--output-template <pattern>` or support smart `-o` syntax:
     * If the `-o` argument contains template tokens (e.g. `%(...)s`, `{...}`) or path separators ending with an extension/template token, treat as an output template.
     * Otherwise treat as directory path (preserving backwards compatibility).
   * Config persistence: Support `"outputTemplate": "%(uploader)s/%(title)s.%(ext)s"` in `config.json`.
2. **Unified Template Token Vocabulary**:
   Support common cross-platform tokens:
   * `%(title)s` / `{title}`: Sanitized media title.
   * `%(id)s` / `{id}`: Platform media identifier.
   * `%(uploader)s` / `{uploader}` / `%(artist)s`: Author/channel name.
   * `%(upload_date)s` / `{date}`: Upload date (`YYYYMMDD`).
   * `%(playlist_index)s` / `%(index)02d` / `{index}`: Track index in batch.
   * `%(ext)s` / `{ext}`: Container or file extension.
3. **Engine Translation Layer**:
   * For `yt-dlp`: Pass directly to `ytdlp` via `-o <template>` (native yt-dlp templating).
   * For `gallery-dl`: Translate tokens to gallery-dl syntax (`-f` / `--filename`).
   * For native HTTP resolvers (`instagram.ts`, new `bluesky.ts`): Evaluate tokens in Node using item metadata and sanitize path segments with `sanitizeFilename` ([src/lib/playlist.ts#L32-L44](file:///x:/Open%20Omni/src/lib/playlist.ts#L32-L44)).
4. **Ledger Alignment**:
   * Since `yt-dlp` returns the final expanded path via `--print after_move:filepath` ([src/lib/ytdlp.ts#L586-L587](file:///x:/Open%20Omni/src/lib/ytdlp.ts#L586-L587)), the ledger accurately records dynamic paths without guessing.

### 1.3 Persistent Preferences in `config.json`

#### Current State in Codebase
* `UserConfig` ([src/lib/config.ts#L36-L53](file:///x:/Open%20Omni/src/lib/config.ts#L36-L53)) supports: `outputDir`, `theme`, `format`, `audioFormat`, `videoFormat`, `subtitles`, `thumbnail`, `metadata`, `cookies`, `cookiesFromBrowser`, `proxy`, `geoBypass`, `geoCountry`, `limitRate`, `sponsorblock`, `sponsorblockRemove`.
* `loadConfig` ([src/lib/config.ts#L93-L244](file:///x:/Open%20Omni/src/lib/config.ts#L93-L244)) reads from `$XDG_CONFIG_HOME/open-omni/config.json` or `~/.config/open-omni/config.json`.
* `resolveRuntimeConfig` ([src/lib/config.ts#L395-L420](file:///x:/Open%20Omni/src/lib/config.ts#L395-L420)) correctly implements the precedence waterfall ([ADR 0006](file:///x:/Open%20Omni/docs/adr/0006-user-configuration.md#L41-L50)).
* **Critical Missing Capability**: `config.ts` has **no write function**. There is no `saveConfig()` or `updateConfig()`.

#### Limitations
1. In the TUI ([src/app.tsx#L793-L812](file:///x:/Open%20Omni/src/app.tsx#L793-L812)), users can cycle theme (`^t`), cycle audio format (`a`), cycle video format (`v`), and toggle subtitles/thumbnails (`s`, `t`). However, these choices **vanish when the process exits**; users must re-toggle them every time.
2. Users who want to permanently set a proxy or rate-limit must manually construct a JSON file by hand in their terminal.

#### Proposed Architecture & Implementation Plan
1. **Implement `saveConfig` in `src/lib/config.ts`**:
   ```ts
   export function saveConfig(updates: Partial<UserConfig>, configPath: string = resolveConfigPath()): void {
     const current = loadConfig(configPath)
     const merged = {...current, ...updates}
     fs.mkdirSync(path.dirname(configPath), {recursive: true})
     fs.writeFileSync(configPath, `${JSON.stringify(merged, null, 2)}\n`, 'utf8')
   }
   ```
2. **CLI Config Subcommand / Flags**:
   * Support `open-omni config set <key> <value>` (e.g. `open-omni config set proxy http://127.0.0.1:8080`, `open-omni config set format mp3`).
   * Support `open-omni config get [key]` and `open-omni config path`.
3. **TUI Interactive Persistence Option**:
   * Provide a setting or prompt on exit/keybind (e.g. `^s`: "Save current format & theme preferences to config.json").

### 1.4 Live Clipboard Watcher Daemon Mode (`--watch`)

#### Current State in Codebase
* `src/lib/clipboard.ts` ([#L14-L23](file:///x:/Open%20Omni/src/lib/clipboard.ts#L14-L23)) executes platform-specific binaries (`pbpaste` on macOS, `powershell Get-Clipboard` on Windows, `wl-paste`/`xclip`/`xsel` on Linux) synchronously via `execFileSync`.
* In `src/cli.tsx` ([#L428-L432](file:///x:/Open%20Omni/src/cli.tsx#L428-L432)), this is only probed once on CLI startup if stdin is a TTY and no URL was passed.

#### Proposed Architecture & Implementation Plan
1. **Daemon Invocation**:
   * `open-omni --watch [options]` (e.g. `open-omni --watch --best -o ~/Downloads`).
   * Runs in persistent foreground terminal mode (or as background service).
2. **Non-Blocking Async Polling**:
   * Using `execFileSync` in a loop spawns a full `powershell.exe` process every second on Windows, causing high CPU spikes.
   * Switch to an async polling loop using `execFile` with an adaptive interval (e.g., 1.5s idle, sleeping when focused elsewhere).
   * For Windows, explore a lightweight Node helper or a persistent background PowerShell process communicating over stdin/stdout.
3. **Deduplication & Queue Lifecycle**:
   * In-memory LRU cache (`Set<string>`) of the last 100 seen clipboard strings to avoid re-triggering while a URL remains copied.
   * Query the Download Ledger via `getCompletedDownload({url})` ([src/lib/ledger.ts#L115-L118](file:///x:/Open%20Omni/src/lib/ledger.ts#L115-L118)); if already downloaded, emit a subtle notice `[watch] Skipping already downloaded URL` without re-fetching.
4. **Desktop Notifications & Terminal Logging**:
   * When a URL is detected, print clean timestamped log line: `[14:20:05] Found URL: https://youtu.be/... → Downloading...`
   * On completion: `✓ Downloaded → ~/Downloads/Video.mp4`.
   * Optional system terminal bell (`\x07`) or native OS notification.

### 1.5 Direct TikTok / Bluesky Embed or `gallery-dl` Routing Improvements

#### Current State & Bugs in Codebase
1. **Missing Bluesky Platform Definition**:
   * In `src/lib/platforms.ts` ([#L10-L20](file:///x:/Open%20Omni/src/lib/platforms.ts#L10-L20)), `PLATFORMS` lists YouTube, X, Instagram, Threads, TikTok, Vimeo, Twitch, Reddit, and Facebook.
   * **`bsky.app` is missing**. As a result, `detectPlatform('https://bsky.app/...')` returns `{key: 'generic', label: 'bsky.app'}` rather than a recognized platform entity.
2. **TikTok Photo Posts Bypassing `gallery-dl`**:
   * In `src/lib/dispatcher.ts` ([#L33-L52](file:///x:/Open%20Omni/src/lib/dispatcher.ts#L33-L52)), `MIXED_OR_PHOTO_DOMAINS` includes X, Instagram, Reddit, Facebook, Pinterest, Flickr, Pixiv, Bluesky, Threads, Tumblr, Weibo.
   * **`tiktok.com` is missing from `MIXED_OR_PHOTO_DOMAINS`**.
   * Consequently, when a user passes a TikTok photo slideshow link (`tiktok.com/@user/photo/...`), it bypasses `gallery-dl` and routes directly to `yt-dlp`. `yt-dlp` fails with `ERROR: No video formats found` or only extracts the background audio. If routed to `gallery-dl`, `gallery-dl` natively extracts all full-resolution slides!

#### Proposed Architecture & Implementation Plan
1. **Immediate Routing Fixes**:
   * Add `{hosts: ['bsky.app'], platform: {key: 'bluesky', label: 'Bluesky'}}` to `PLATFORMS` in `src/lib/platforms.ts`.
   * Add `'tiktok.com'` and `'vt.tiktok.com'` to `MIXED_OR_PHOTO_DOMAINS` in `src/lib/dispatcher.ts`.
2. **Native Bluesky Resolver (`src/lib/bluesky.ts`)**:
   * Following the architectural success of the Native Instagram Embed Resolver ([ADR 0014](file:///x:/Open%20Omni/docs/adr/0014-native-instagram-embed-resolution.md)), Bluesky posts can be resolved natively via public REST APIs without spawning any subprocess.
   * Bluesky AT Protocol offers an unauthenticated public AppView API:
     `GET https://public.api.bsky.app/xrpc/app.bsky.feed.getPostThread?uri=at://{did_or_handle}/app.bsky.feed.post/{rkey}`
   * Returns:
     * Full-size original images: `https://cdn.bsky.app/img/feed_fullsize/plain/{did}/{cid}@jpeg`
     * Video manifests: HLS playlist URLs for attached video records.
   * **Advantage**: Zero external binary dependencies, response time <150ms (compared to 2–4s for `gallery-dl`), zero cookie requirements for public posts.
3. **Native TikTok oEmbed & Embed Resolver (`src/lib/tiktok.ts`)**:
   * Query TikTok's public oEmbed endpoint (`https://www.tiktok.com/oembed?url=...`) to retrieve author metadata, description, and thumbnail without authentication.
   * For slideshow posts, parse the embed or fallback to `gallery-dl`.

## 2. Codebase Architecture & Hygiene Improvements

### 2.1 Decomposing `src/app.tsx` (>1100 Lines) into Modular Views/Hooks

#### Current State
* `src/app.tsx` is currently **1,194 lines long** and acts as a monolithic God Component.
* Responsibilities entangled within `InnerApp` ([#L233-L1194](file:///x:/Open%20Omni/src/app.tsx#L233-L1194)):
  1. Component state: 11 distinct `useState` hooks and 5 `useRef` hooks ([#L287-L304](file:///x:/Open%20Omni/src/app.tsx#L287-L304)).

  3. Single download execution & error handling: 107 lines ([#L341-L448](file:///x:/Open%20Omni/src/app.tsx#L341-L448)).
  4. Batch playlist queue loop & error handling: 120 lines ([#L450-L570](file:///x:/Open%20Omni/src/app.tsx#L450-L570)).
  5. URL probing, binary verification, and dispatcher dispatch: 175 lines ([#L595-L770](file:///x:/Open%20Omni/src/app.tsx#L595-L770)).
  6. Keyboard input parsing: 50 lines ([#L791-L841](file:///x:/Open%20Omni/src/app.tsx#L791-L841)).

│   └── useAppHotkeys.ts            # useInput bindings, shortcuts, format cycling (~70 lines)
└── components/views/
    ├── playlist-scope-view.tsx     # Extracted from app.tsx L994-1029
    ├── playlist-items-view.tsx     # Extracted from app.tsx L1031-1062
    ├── playlist-quality-view.tsx   # Extracted from app.tsx L1064-1092

### 2.2 Unified Engine Dispatcher Interface

#### Current State
* In `src/lib/dispatcher.ts`, media routing is implemented as an ad-hoc procedural waterfall.
* Adding a new resolver (e.g. Bluesky or TikTok) requires hacking more nested if-statements across `probeUnified` and `downloadUnifiedItem`.

#### Proposed Architecture: The `MediaEngine` Contract
Define a formal, pluggable interface in `src/lib/engine.ts`:

```ts
export interface EngineProbeContext {
  url: string
  signal?: AbortSignal
  cookieFile?: string
  cookieHeader?: string
  proxy?: string
  limitRate?: string
  geoBypass?: boolean
  geoCountry?: string
  onStatus?: (status: string) => void
}

export interface EngineDownloadContext {
  item: PlaylistEntry
  destDir: string
  filename?: string
  totalCount?: number
  choice?: DownloadChoice
  subtitles?: SubtitleOptions
  thumbnail?: ThumbnailOptions
  metadata?: MetadataOptions
  signal?: AbortSignal
  cookieFile?: string
  cookieHeader?: string
  proxy?: string
  limitRate?: string
  onProgress?: (progress: DownloadProgress) => void
  onProcessing?: () => void
}

export interface MediaEngine {
  readonly name: string
  readonly priority: number // Higher priority engines are evaluated first
  canHandle(url: string): boolean
  probe(url: string, ctx: EngineProbeContext): Promise<UnifiedProbeResult>
  download(ctx: EngineDownloadContext): Promise<string>
}
```

### 2.3 Error Sanitizer Hardening

#### Current State & Vulnerabilities
* `maskProxyCredentials` in `src/lib/ytdlp.ts` ([#L474-L480](file:///x:/Open%20Omni/src/lib/ytdlp.ts#L474-L480)) only masks basic URL credentials (`http://user:pass@host`).
* Leaves API Tokens (`?access_token=...`, `?token=...`, `?sig=...`), Authorization Headers (`Bearer`, `Basic`), and Cookies vulnerable in error dumps.
* Top-level error handlers in `src/cli.tsx` print raw un-sanitized error objects.

#### Proposed Architecture: `src/lib/sanitizer.ts`
Create `src/lib/sanitizer.ts` with comprehensive regex redaction, and wrap top-level CLI error listeners.
